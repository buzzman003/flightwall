YOUR OWN FLIGHT: FLIGHTAWARE AEROAPI (OPTIONAL, BILLED SEPARATELY)

1. Open https://www.flightaware.com/commercial/aeroapi/ and create your own
   AeroAPI account. Review current pricing, allowed uses, availability and your
   account's spending controls before enabling this feature. The Personal tier
   currently has no monthly minimum and up to $5 free monthly query usage; the
   Standard tier has a $100 minimum and is not needed for this household display.
   This app does not include an AeroAPI subscription or access key.

2. In the Batocera SSH terminal, store the key with the hidden input prompt:

   /userdata/roms/ports/.data/flightwall/flightwall store-secret flightaware

   Paste your key when asked. The key is saved privately outside app releases.
   Do not paste the key into ChatGPT, source code, a screenshot or public URL.

3. Set your airline code. Replace YOUR_CODE with your own 2- or 3-character code:

   /userdata/roms/ports/.data/flightwall/flightwall config --set airline YOUR_CODE

   For example, DAL is Delta's ICAO code; use it only if that is your airline.
   Numbers already containing an airline prefix retain their existing prefix.
   A bare calendar number requires the code you provide; the app does not guess.

4. Enable the feed:

   /userdata/roms/ports/.data/flightwall/flightwall config --set flightaware_enabled true

   0.4.5 defaults: status eligibility from four hours before scheduled departure
   to six hours after scheduled arrival. Position queries begin one hour before
   departure or once the provider reports departure. After initial association,
   one request every120seconds alternates status/position (about4minutes each).
   Arrival-gate/tracking-ended/blocked reports stop further requests for that leg.

   All operating/watch calls share the240-request UTC-day limit and a separate
   $5 monthly app reservation limit at checked nominal fees. Set a lower local
   limit if desired; the code rejects values above$5. This is not an account-wide
   spending control and does not include other apps, taxes, fees or credits.
   Rates expire after90days pending review. See RELEASE-0.4.5.txt for details.

   /userdata/roms/ports/.data/flightwall/flightwall config --set flightaware_monthly_limit_usd 5

5. To disable paid requests:

   /userdata/roms/ports/.data/flightwall/flightwall config --set flightaware_enabled false

Matching requires exactly one canonical airline/flight number, IATA route and
scheduled-departure-window match within six hours. Ambiguous matches and
contradictory pagination are skipped; a nearest match is never guessed. Codeshares,
last-minute aircraft/flight changes, extreme delays and provider coverage can
prevent a match. Positions more than five minutes old are hidden. A feed outage
retains the calendar; it does not fabricate an aircraft moving along the route.

Provider position altitude is converted from hundreds of feet to feet. Ground
speed is in knots. These values are informational, not operational flight data.
No real account or paid live endpoint was exercised during the included tests.

OFF-DUTY NEARBY TRAFFIC: ADSB.LOL (OPTIONAL COMMUNITY FEED)

This uses https://api.adsb.lol/ without a paid FlightAware subscription. The
community provider describes free ad-hoc/feeder access and optional sponsorship
for more quota. Availability, access rules and coverage can change; continuous
unlimited access is not promised. The app currently makes unauthenticated local
circle requests at most once per minute while off duty. Your roster flights
retain priority. No paid fallback or subscription is enabled automatically.

First save your own home/display pin privately through setup. Enabling nearby
traffic sends that pin to ADSB.lol as query coordinates; it does not send your
calendar. Do not paste the pin into chat or commit it. After installing 0.4.2,
use the existing pin with a five-statute-mile radius:

   /userdata/roms/ports/.data/flightwall/flightwall config --set nearby_radius_miles 5 --set nearby_enabled true

This is a horizontal radius, not a height/altitude limit or a promise that a
plane is directly overhead. The app requests a containing provider circle and
then filters the actual distance precisely. The override accepts 0.1-250 miles.
Set nearby_radius_miles to null to preserve the legacy nearby_radius_nm setting;
upgrading never silently reinterprets old nautical-mile values as statute miles.

The north-up map shows received positions around a home marker, with details
for the three nearest aircraft and at most forty nearest points. Callsign,
registration/tail and type appear only when the provider supplies valid values.
Origin and destination are unavailable from this position feed and are not
guessed. Optional 0.4.7 AeroAPI enrichment is described below. The bundled
regional inset includes water/roads/runways; there is no moving estimate
between observations or automatic online map-tile query.

Only positions with a provider-derived age of 0-120 seconds appear. Explicit
ground reports are excluded; an unknown altitude remains labeled unknown.
Age comes from the provider snapshot time minus position age, not download
receipt time. Invalid, future, ground and stale fixes are discarded; every TV
frame rechecks age even if the backend stops. Failed feeds clear traffic.
Changing the pin/radius hides a response from the old query immediately.
"No fresh aircraft" can mean no coverage, no nearby aircraft or unavailable
data; it is not proof that the sky is empty.

The admin TV route receives aircraft coordinates and home-relative offsets.
Maintenance status removes absolute aircraft coordinates when offsets are
present, so the response does not directly reconstruct the private home pin.

Disable it with:

   /userdata/roms/ports/.data/flightwall/flightwall config --set nearby_enabled false

LOCAL WEATHER: NATIONAL WEATHER SERVICE (OPTIONAL, NO API FEE)

The NWS API supplies public U.S. forecast data without an API usage fee. No
FlightAware subscription or weather API key is needed. Rate limits, outages and
geographic coverage still apply. This feature is a forecast reminder, not an
aviation/weather safety service or a guarantee that cushions will stay dry.

Choose a coarse forecast point appropriate for your area. It is separate from
the phone/home geofence and is not copied from that pin automatically. On the
local SSH terminal, replace LATITUDE and LONGITUDE below with your chosen
numeric values before running the command; these words are placeholders:

   /userdata/roms/ports/.data/flightwall/flightwall config --set weather_latitude LATITUDE --set weather_longitude LONGITUDE --set weather_enabled true

NWS receives the configured query coordinates. The app does not automatically
coarsen a precise value, so enter the coarse point you intend to disclose.
Weather coordinates stay in private config and cannot be set through remote
tools or read from public configuration/status. The weather cache stores only
normalized forecast fields and a location identity hash, not raw provider
payloads or coordinates. Enabling weather without a valid point shows an
unavailable/unconfigured state rather than guessing your location.

The card shows today's and tomorrow's daytime high/nighttime low in Fahrenheit,
with dates and an overnight rain reminder. All boundaries use the board's
configured time zone. Before 08:00, the reminder covers the remaining current
night until 08:00. From 08:00 it targets the coming 18:00-08:00 period; after
18:00 it covers the remaining hours. DST changes are included. The TV labels
the window as NOW-08:00 LOCAL or 18:00-08:00 LOCAL.

A fresh hourly rain mention or peak hourly precipitation chance of at least
20% gives RAIN POSSIBLE / PUT CUSHIONS IN. That percentage is the highest hourly
chance in the covered window, not a probability calculated for the whole night.
Incomplete data may still establish rain possible and is labeled PARTIAL DATA.
Low chance requires complete, fresh probability coverage for all remaining
hours and no rain mention. Missing/null/overlapping hours never establish low
risk. Unknown or stale coverage says to check an updated forecast. Missing
daytime data does not suppress a valid hourly rain warning.

Forecast requests run separately from calendar/control work, every
15 minutes; point-to-grid mapping refreshes every 24 hours. A two-hour-old fetch
or twelve-hour-old forecast issuance is stale. Dates, windows and freshness are
also checked each frame; cached data is not relabeled as newly observed.
The TV identifies NWS and its forecast time. See weather.gov for full forecasts.

To disable weather:

   /userdata/roms/ports/.data/flightwall/flightwall config --set weather_enabled false

OPTIONAL 0.4.7 FLIGHT CONTEXT

These independent choices default off. Configure them locally after installing
0.4.7. No extra key is needed for the fixed official public feeds. They query
public airport identifiers/coordinates, not the household's saved home point.
Commands suppress the CLI's full private configuration output:

   /userdata/roms/ports/.data/flightwall/flightwall config --set trip_weather_enabled true --set national_radar_enabled true --set airport_alerts_enabled true >/dev/null

Trip METAR/TAF and airport NWS poll at fifteen-minute intervals. National NOAA
observed radar polls every ten minutes; FAA airport advisories every five.
Cards require an eligible day-before/flight-day/layover context and fresh data.
Radar is current observation, not tomorrow's forecast. Airport forecasts are
dated in the configured display time zone. Read official aviation briefings
for operational decisions. See RELEASE-0.4.7.txt for freshness and field limits.

To prioritize only the current flight's flight views during its focus window:

   /userdata/roms/ports/.data/flightwall/flightwall config --set flight_focus_only true >/dev/null

The operating geographic inset appears only with an actual fresh matched fix.
It fits origin/destination and progressively narrows toward destination. Wide
views have limited geographic detail; close runway references are not charts.
Actual surface/taxi display depends on provider ground-position coverage.
Neither a roster nor a phone report is substituted for an aircraft position.

Optional nearby origin/destination metadata requires the separately configured
AeroAPI key and flightaware_enabled setting. After reviewing paid use, enable:

   /userdata/roms/ports/.data/flightwall/flightwall config --set nearby_enrichment_monthly_limit_usd 1 --set nearby_enrichment_enabled true >/dev/null

This shares the existing $5 application request budget; its additional subcap
is at most $1 or 20% of the monthly allowance, plus a low daily sublimit. One
lookup per five minutes, cached results and operating-first polling protect
the owner's flight allowance. Unique association and freshness are mandatory.
Unavailable, ambiguous or missing routes stay ROUTE N/A. It is not a provider-
account-wide hard spending limit. Set any of the above boolean choices to
false with the same local command to disable that connection/preference.

0.4.5 AUTOMATIC WEATHER AND OPERATING STATUS

Weather refresh runs independently of card rotation while either the display
or background service is running. No close/reopen is required for normal
15-minute polling. Source forecast issuance may change less often than queries;
the card preserves source/age and missing/stale data never means dry weather.
AM/PM is presentation only; all stored aware timestamps and DST rules remain.

The operating card distinguishes actual/estimated gate or runway times from
provider-scheduled baselines, reports early/late minutes, and expires stale
verdicts each frame. A cancelled/tracking-ended provider flag is not proof of
airline cancellation. Check the airline for operating decisions. No account
or key is provisioned by a release; no paid provider test has been performed.

FLIGHT WALL 0.4.1: SHORT DINNER COMMANDS

This is the historical 0.4.1 release-time record. The owner has since activated
published 0.4.2; its preservation, TV/provider checks and remaining Alexa routing
limitations are recorded in VALIDATION.txt and RELEASE-0.4.2.txt. The deployment
paragraphs below describe the earlier 0.4.1 checkpoint.

Published signed Linux release:
https://github.com/buzzman003/flightwall/releases/tag/v0.4.1
Linux validation passed 562 tests and 314 subtests without skips or failures,
including real offscreen OpenGL and native upgrade/recovery checks from both
0.3.0 and published 0.4.0. Maximum required glibc remains 2.36.
Detailed publication and deployment evidence is recorded in VALIDATION.txt;
source changes alone do not update Batocera or Alexa.

The Alexa adapter adds separate today/tomorrow dinner intents. Candidate direct
forms are: "Alexa, ask Flight Wall to set dinner today to chicken teriyaki" and
"Alexa, ask Flight Wall to set dinner tomorrow to tacos and rice". Once inside
the confirmed skill session, say "dinner today is chicken teriyaki" or
"dinner tomorrow is tacos and rice". Literal-day forms keep the free-text meal
separate from the date. Another date still uses "set dinner for Friday", then
the meal. Alexa receives no flight/calendar data through these voice routes.

The adapter computes today/tomorrow using the board's current timezone, including
calendar-day boundaries across daylight-saving changes. A short acknowledgement
reads the actual saved meal/day. Expired-window, hidden-card and uncertain-write
warnings remain. Ambiguous date words captured as the meal ask for clarification
instead of silently saving the meal for today. Existing request deduplication,
selected-date follow-up and same-date replacement remain in place.

Dinner cards retain the configured display window (default 14:30-19:00) and
existing custody visibility rules, and join the normal rotation. These commands
do not send messages to children or create Google Calendar events.

Invocation reliability is a separate issue. On the owner's current Alexa setup,
some direct dinner requests were routed to native announcements instead of the
skill. The published 0.4.1 Lambda ZIP is deployed, its AWS code checksum matches
the package, and the en-US model built successfully with 29 intents. Inside a
confirmed skill session, typed today/tomorrow simulator commands both saved
correctly through the live board connection. Independent reads verified the
meal dates and 14:30-19:00 Central windows across the daylight-saving change.
Exact-ID cleanup removed both disposable cards and preserved unrelated data.
These checks do not establish physical Echo routing or reliable direct phrases.
The board has now activated 0.4.1. Authenticated SSH verified the running GUI,
healthy startup, cleared pending/awaiting-health flags and 0.4.1 version floor.
The original 0.3.0 recovery helper remains pinned. A verified private backup and
post-update comparison confirmed data and credential preservation; see
VALIDATION.txt for the precise configuration differences. Owner TV confirmation
is still pending. Physical dinner-help and explicit skill-open attempts still
failed; fresh Lambda logs were unavailable after the AWS login session expired.
An explicitly selected Skills action in an Alexa Routine remains unverified.

This release does not add native Alexa timer mirroring, Home Assistant, email
export, IFTTT or shopping geofences. Shopping work is paused by the owner.
Games, credentials, mutable settings, original recovery helper and trust key
must remain outside/reused across the signed next-launch update.

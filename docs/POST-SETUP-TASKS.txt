PRESERVATION REQUIREMENT

Credentials, logins, caches, artwork, calendar roles and mutable settings stay
in /userdata/system/configs/flightwall, outside versioned releases. Back up this
data privately before an upgrade; never place it in release files, source
control, a public website or chat. Preserve logins during app updates while
recognizing that provider expiry/revocation may independently require sign-in.
Keep the original pinned known-good recovery helper and trusted public key.

ALEXA FOLLOW-UP

The original 0.3.0 interaction model reused Title with inconsistent slot types.
Amazon's build requires a reused slot name to have the same type and meaning.
The 0.4.0 source model corrects this. Preserve appointment confirmation and
validate standard/unlisted titles, follow-up title prompts and live speech.
Custom slots may accept unlisted values; do not promise SearchQuery-equivalent
recognition without verification.
https://developer.amazon.com/en-US/docs/alexa/custom-skills/create-the-interaction-model-for-your-skill.html#intent-and-slot-name-requirements

The explicit phrase "Alexa, open Flight Wall skill" passed a real Echo check
for 0.3.0. Simpler variants had inconsistent routing; the cause is unproven.
Use disposable synthetic cards when checking speech, and remove only their
verified IDs. Source/simulator tests do not prove arbitrary spoken-title support.

DEPLOYMENT LONGEVITY

Review the actual hosting account's plan, quotas, expiry and billing choices
before relying on long-term Alexa availability. A free allowance does not by
itself establish indefinite hosting. Keep account balances, contact details,
identifiers and billing history out of public documentation. Deployment/billing
changes require their own authorization; this task file enables no such changes.
